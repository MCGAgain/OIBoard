# OIBoard 移动端阶段工作交接与排查记录 (HANDOFF)

本文档记录数据总览看板的核查根因、修改说明及文案专业化对照表，供真机连接真实服务器验收时查验。

## 1. 核心问题根因核查（一句话归纳）

1. **热力图“缺点”与早期月份不可见**：
   - **根因**：热力图此前采用了横向滚动容器且默认滚动至最新一周，导致 2024、2025 年集中在早春与年中的活跃格子被滚出了手机屏幕可见范围，并非后端数据缺失。
   - **修复**：重构为 53 列 × 7 行整年一屏自适应画布（彻底移除横向滚动），动态按屏幕宽度计算紧凑方形方格（~5–6dp），顶部标注稀疏月份（1、3、5、7、9、11月），左侧标注周一、周三、周五；支持点击单格直接在下方展示“日期 + 提交数 / 通过数”；集成 Debug 日志比对确保服务端非零天数与实际绘制非零格数 100% 一致；补齐 AcWing 等全量平台筛选。

2. **累计曲线全为 0**：
   - **根因**：后端曲线数据由 `GET /api/stats/overview` 内部字段 `climbing_curve` 返回（结构为 `[{"date": "...", "ac": 123, "new_ac": 2}]`），但移动端 DTO 声明为 `cumulative_ac`，导致反序列化未能识别字段而全部回退为默认值 0，绘制出贴底直线。
   - **修复**：在 `ClimbingCurvePointDto` 中使用 `@SerialName("ac")` 与 `@SerialName("new_ac")` 正确映射；当数据为空或全部为 0 时展示图表占位图标与“暂无数据”，不再绘制贴底死线；并实现按需懒加载。

3. **曲线平滑与绘制开销**：
   - **根因**：常规三阶样条插值（如 Catmull-Rom）在处理离散阶跃数据时会产生过冲甚至局部回落，破坏累计曲线“单调不减”的数学特性。
   - **修复**：默认采用真实物理折线；平滑模式采用严格保持单调的 **Fritsch-Carlson 三次 Hermite 插值算法**，数学上杜绝低于 0 或高于区间的过冲；对 365 天长数据序列按拐点与关键跳跃点自适应降采样至 ~50 点，大幅降低 Canvas 重绘 CPU/GPU 开销。

## 6. 本轮关键优化与安全性改造记录

### 1. 提交页流式解析与大 limit 筛选优化
- **后端现状核验**：经代码核查与真实 GET 测试，后端 `/api/stats/submissions` 仅接收 `platform` 和 `limit` 参数，不支持服务端按日期、状态、标签筛选。
- **真实响应体大小**：真实服务器在 `limit=2000`（用户当前 1568 条提交）时，响应体实际大小为 **894,916 字节 (873.94 KB)**。
- **流式筛选落地方案**：
  - 默认无额外筛选时仅请求 `limit=100`；
  - 当用户激活状态（AC/未通过）、日期区间（今天/7天/30天/今年/自定义）或标签筛选时，按需请求 `limit=2000`；
  - 采用 Android 原生 `android.util.JsonReader` 直接接入 OkHttp 的 `byteStream()` 进行流式解析，边流式读取边按条件过滤，只将匹配的条目实例化为 `SubmissionDto` 并追加到内存结果集中，上限达到 150 条时即停止扩充，避免将近 900KB 的庞大 JSON 完整读入内存 String，内存中最多保留 150 条记录。

### 2. 各页面 30–60 秒内存时效缓存与写操作失效机制
- **各页面缓存时效**：
  - **数据总览 (Overview)**: **60 秒**
  - **比赛日历 (Contests)**: **60 秒**
  - **提交记录 (Submissions)**: **30 秒**
  - **错题集 (Mistakes)**: **30 秒**
- **交互逻辑**：时效内切回页面直接展示，零网络请求与零等待；时效过期后触发静默后台刷新，保持当前列表展示无白屏感；下拉刷新（Pull to Refresh）无视缓存强制向服务器重拉。数据容量均设置了 100–150 条的严格上限。
- **写操作成功 $\rightarrow$ 联动缓存失效对照表**（已通过 `AppCacheManager` 响应式总线实现）：

| 写操作类型 | 触发位置 | 立即失效的页面缓存 | 联动响应行为 |
| :--- | :--- | :--- | :--- |
| **加入错题** (`POST /api/mistakes`) | 提交页入错题 / 错题页新增 | **提交页** (`SUBMISSIONS`) + **错题页** (`MISTAKES`) | 提交页错题键索引更新；错题页即时清空缓存并重拉最新错题与统计计数 |
| **编辑错题** (`PUT /api/mistakes/{id}`) | 错题页编辑表单保存 | **错题页** (`MISTAKES`) + **总览页** (`OVERVIEW`) | 错题详情与列表即时刷新；总览页统计大盘失效并静默拉取 |
| **删除错题** (`DELETE /api/mistakes/{id}`) | 错题页删除确认 | **错题页** (`MISTAKES`) + **总览页** (`OVERVIEW`) | 错题项移除并重算计数；总览页大盘失效并刷新 |
| **复习推进** (`POST /api/mistakes/{id}/review`)| 错题页复习确认 | **错题页** (`MISTAKES`) + **总览页** (`OVERVIEW`) | 推进艾宾浩斯复习周期与下次复习日；总览页连续打卡/今日指标失效并刷新 |
| **掌握切换** (`POST /api/mistakes/{id}/toggle-master`)| 错题页掌握切换确认 | **错题页** (`MISTAKES`) + **总览页** (`OVERVIEW`) | 移入已掌握或待复习分类；总览页统计大盘失效并刷新 |
| **账号增/删/改** (`POST/PUT/DELETE /api/accounts*`)| 设置页账号管理弹窗 | **总览页** + **提交页** + **比赛页** | 平台绑定关系改变，三大核心看板数据全部失效并重新按需拉取 |
| **设为主账号** (`POST /api/accounts/{id}/primary`)| 设置页设为主账号确认 | **总览页** + **提交页** + **比赛页** | 主账号切换，看板数据全部失效并重新拉取 |
| **单账号/全网同步** (`POST /api/accounts/{id}/sync` / `/api/sync`) | 设置页同步确认 | **总览页** + **提交页** + **比赛页** | 服务端爬虫抓取新数据，移动端核心数据全部失效并刷新 |
| **比赛抓取同步** (`POST /api/contests/sync`) | 比赛页顶部同步确认 | **比赛页** (`CONTESTS`) | 比赛日程列表缓存立即失效并拉取最新全网赛程 |

### 3. Canvas 绘制阶段零对象分配治理
- **自查第 7 项（绘制阶段是否有每帧分配对象）确认**：明确回答为 **“有”**（优化前确实存在每帧分配）。
- **彻底消除对象类型清单**：
  - `HeatmapCanvas`（热力图）：消除绘制阶段的 365 次 `LocalDate.plusDays()`、365 次 `DateTimeFormatter.format()`、365 次 `CornerRadius`、`listOf(weekLabels)`、`Offset` 等每帧对象分配。全部 365 格位置、颜色及字符串均移至 `remember` 预计算，绘制循环仅读取预生成的数据列表。
  - `ClimbingCurveCanvas`（累计曲线）：消除每帧新建的 `Path()`（2个）、`PathEffect.dashPathEffect()`、`floatArrayOf()`、`listOf()`、Monotone 插值中的 4 个 `FloatArray`、`Stroke` 以及点位映射 `List<Offset>`。曲线 `linePath` 与 `fillPath` 仅在数据或容器尺寸变化时在 `remember` 中重建，绘制阶段只读路径对象。
  - `DailyEffortCanvas`（每日提交柱状图）：消除每帧新建的 `CornerRadius`、`PathEffect`、`floatArrayOf()`、`listOf()` 及循环内的 `Offset`/`Size` 分配，所有柱状体几何参数移至 `remember` 预计算。
  - `PlatformsDonutCanvas`（平台分布环形图）：消除在每个平台扇区循环内新建的 `Stroke(cap = Butt)`，扇区角度与圆弧样式在 `remember` 中预生成。

### 4. 错题详情精准查询方案与参数设计
- **后端接口现状**：后端无 `/api/mistakes/{id}` 单条查询路由，但 `GET /api/mistakes` 返回的列表项中已完整包含了所有详情字段（`notes`, `key_point`, `problem_url`, `tags` 等）。此外后端 `/api/mistakes/keys` 仅返回 `platform:problem_id` 字符串列表，不包含条目自增 id。
- **选定方案**：
  - 在错题页中，点击错题卡片直接复用列表中已有的完整 `MistakeItemDto` 对象展示详情弹窗，杜绝多余的网络请求；
  - 在提交记录页中点击“已入错题 · 笔记”时，发起精确参数查询：
    - **方法**: `GET /api/mistakes`
    - **完整参数**: `platform={sub.platform}&search={sub.problem_id}&page=1&page_size=20`
    - **为什么 page_size 不能为 1**：后端 search 是 SQL `LIKE %search%` 模糊匹配，当搜索例如 `100` 时可能会同时命中 `1001`、`1002`，若限制 `page_size=1` 则极易返回前序的错误题目。设置 `page_size=20` 并在移动端使用 `it.platform.equals(sub.platform, ignoreCase = true) && it.problem_id.equals(sub.problem_id, ignoreCase = true)` 进行内存精确双重匹配，彻底杜绝跨平台及同名前缀冲突。

### 5. 敏感字段与安全隔离
- **掩码控制**：系统设置页中的“Cookie 凭据”、原密码、新密码、确认密码输入框全部强制配置 `visualTransformation = PasswordVisualTransformation()`。
